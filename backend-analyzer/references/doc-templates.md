4. 带 Authorization: Bearer <token> 调 GET /api/students 体会拦截器流程

## 术语速查
| 术语 | 含义 |
|---|---|
| JWT | 无状态登录令牌，本项目拦截器用它校验身份 |
| N+1 查询 | 查列表后对每行再单独查一次库，性能杀手，见 student 模块 |

## 4. 全局写作守则

- 读者是"第一次看这个项目的后端学习者"：先说结论/意图，再给细节；每个缩写第一次出现时解释。
- **降低复杂度的硬节奏**：一屏一个重点——功能小节正文尽量表格化（步骤表），叙述文字每段 ≤ 3 句；单份模块文档超过 ~250 行时自查是否把细枝末节写了进来（该进流程图的不写成文字，该进表格的不写成段落）。
- **接口的书写格式（报告会自动渲染成方法色徽章）**：正文中提到接口一律写成 `METHOD /完整路径`（如 `POST /api/courses/{id}/enroll`，方法和路径之间一个空格）；功能清单表的方法列只写方法词（GET/POST/PUT/DELETE/PATCH），路径单独放"路径"列；不要写成中文夹注（"POST接口/api/xxx"）或把路径和方法拆开摆放。
- **三层导航让模块"分得开、连得上"**：模块位置图（它和谁有关系）→ 功能清单（它有什么）→ 功能跳转地图（用户操作怎么走）。三层都齐，读者才不会迷路。
- 每个论断带 `文件:行号`；无依据的判断写 `> ⚠️ 推测：`。
- 代码片段只贴关键的（≤10 行），贴之前想一想"读者需要看到这行才能信"。
- 文件路径一律相对项目根目录。
- 不写空话（"建议加强代码质量"），每条建议可执行。
